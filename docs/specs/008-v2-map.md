# Spec 008 — `/v2/map` route + shared sitemap parser

Task slug: `v2-map`. Branch: `feat/v2-port-008-v2-map`.

## Why
v2 map differs from v1 in two ways: request `sitemap` is an enum
(`skip|include|only`, default `include`) replacing v1's `ignoreSitemap` boolean, and the
response `links` is an array of OBJECTS `{url, title?, description?}` instead of `string[]`.
The sitemap parser is also needed by the crawl task later, so it lands as a shared module now.

## Scope

### 1. NEW `src/crawler/sitemap.ts`
```ts
export async function fetchSitemapUrls(siteUrl: string, opts?: { maxDepth?: number; limit?: number }): Promise<string[]>
```
- Fetch `${origin}/robots.txt` FIRST and honour `Sitemap:` directives (absolute or relative);
  fall back to `${origin}/sitemap.xml` when none are found.
- Support sitemap INDEX files (`<sitemapindex>` → recurse into child sitemaps) up to
  `maxDepth` (default 3) and a `limit` cap (default 5000) on returned URLs.
- Handle gzipped sitemaps (`Content-Encoding: gzip` via `DecompressionStream` — no dependency)
  and `.xml.gz` paths.
- Extract `<loc>` values (both `<urlset><url>` and `<sitemapindex><sitemap>`), resolve
  relative URLs against the sitemap's own URL, dedupe, filter to http(s).
- Reference implementation to port the LOGIC from (read-only; write fresh code):
  `git show origin/crawl:src/utils/sitemapParser.ts`.
- Fail soft: any fetch/parse error → return what was collected (never throw); the route
  decides what that means.

### 2. NEW `src/v2/map.ts`
```ts
export class V2Map extends OpenAPIRoute { schema = {...}; async handle(c: AppContext) {...} }
```
Request (zod): `url: z.string()` (required), `search: z.string().optional()`,
`sitemap: z.enum(["skip","include","only"]).default("include")`,
`includeSubdomains: z.boolean().default(true).optional()`,
`ignoreQueryParameters: z.boolean().default(true).optional()`,
`limit: z.number().int().min(1).max(5000).default(5000).optional()`,
`timeout: z.number().default(60000).optional()`, `location: z.string().optional()`.

Response 200: `{ success: z.literal(true), links: z.object({ url: z.string(), title: z.string().optional(), description: z.string().optional() }).array() }`.

Behaviour:
- `sitemap: "only"` → return ONLY URLs from `fetchSitemapUrls` (no browser at all).
- `sitemap: "skip"` → browser discovery only.
- `sitemap: "include"` (default) → browser discovery, then merge sitemap URLs (dedupe).
- Browser discovery: REUSE the existing upstream implementation in `src/webMap.ts`.
  Make the minimum change there: export the module-private `discoverLinks` (and
  `getBrowser` if needed) so `src/v2/map.ts` can import them. Do NOT restructure or
  rename anything else in that file; `/v1/map` behaviour must remain byte-identical.
- Map the merged URL list to `[{url}]` objects (no title/description — enrichment is
  explicitly out of scope), dedupe, apply `limit` (slice), preserve discovery order.
- `ignoreQueryParameters: true` → strip query strings for dedupe purposes while keeping
  the original URL as the returned value.
- Errors: browser failure with `sitemap !== "only"` → if the sitemap branch produced
  URLs, return those (success) else return 500 with `{success:false, error:"Map failed"}`.
- No `title`/`description` enrichment; no crawl; no external APIs.

### 3. `src/index.ts`
Add `import { V2Map } from "./v2/map";` and `openapi.post("/v2/map", V2Map);`. Nothing else.

- Mock `../../src/browser` and the sitemap module as needed; no real network.
